# Dependency-graph check (madge)

Generated with `npx --yes madge` (dev tooling only — madge is NOT a dependency of this
package) on 2026-08-23, Node 24, for v1.1.0. Reproduce the first check with `npm run arch`
and the whole file with `npm run arch:graph`.

Graphviz `dot` is NOT installed on the machine that produced this file, so no
`dependency-graph.svg` image was rendered; the text graph below is the artifact.
With graphviz available, `npx --yes madge --image docs/architecture/dependency-graph.svg
--extensions js governor fitness simulation dataplane demo shared` produces the picture.

The graph is the machine-checkable form of the hexagonal claim, and fitness function F7
asserts the same rules from inside the test suite: `governor/carbon-governor.js` and
`governor/harness.js` import nothing, `governor/gate.js` imports only `kaiban-distributed`
and the core, `shared/*` are leaves, the adapters (`simulation/`, `dataplane/`, `demo/`)
import only `governor/`, `shared/` and their own folder — never each other — and every
adapter that actuates imports `governor/harness.js`.

`tools/check-numbers.js` appears as a dependency of `fitness/props.js` (fitness function
F12 reads its registry) even though `tools/` is not one of the folders madge is pointed at.

"Orphans" below are the entry points: runnable scripts (`npm run …`) and test files.
Nothing imports them, which is what an entry point is.
