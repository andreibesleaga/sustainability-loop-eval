## Reading this, plainly

The governance gate this package evaluates is not a mock: it is `kaiban-distributed`'s
shipped `ActionGate`, exercised in-process with the Carbon-Verdict Governor as its
validator. Across 15,011 property-test cases and static checks, every property held: the gate
resolves to the single most-severe verdict (F1, F9), fails closed on internal errors and
bad input while treating `enabled:false` as an honest all-or-nothing deployment switch
rather than a bypass (F2), its severity ladder is monotone with exact rung boundaries
(F3), nothing above `degrade` runs without an approval object and `terminate` runs under
no approval at all (F4), every attempted operation leaves exactly one audit record
carrying its own operation type (F5), the audit chain verifies and catches edits (F6) —
though only an external anchor catches truncation (F10) — the governance core and the
actuation harness have zero imports and every actuating adapter goes through the harness
(F7), the whole thing is deterministic and reproducible (F8), the core's own invariants
hold (F11), and the numbers in the documentation still match the files they are drawn
from (F12).

## The one upstream gap this found

F2's rogue-validator sub-case is not a formality. The shipped gate ranks verdicts with
`GATE_ACTION_SEVERITY`, which has no entry for an action that is not on the ladder; the
sort comparator then returns `NaN` and the ordering silently degrades to insertion
order. Measured on `kaiban-distributed@2.0.0`: given the verdict set
`[allow, "not-a-rung", terminate]`, the shipped gate answers **allow** — an off-ladder
verdict does not merely pass through, it can mask a real `terminate`.
`governor/gate.js`'s `gated()` re-aggregates fail-closed whenever any verdict is off the
ladder and keeps the shipped answer as `rawAction`, so nothing in this package acts on
the masked verdict and the gap stays visible. It is a real upstream defect and is to be
reported upstream (ADR-002, ARCHITECTURE section 11).

## What was skipped or worth noting

Nothing was skipped. F6's tamper sub-case is runnable because `AuditLog.records()`
exposes live record objects — which is also exactly why the chain is tamper-*evident*
rather than tamper-*resistant*, and why F10 exists. F7 and F12 run against the real
current state of the repository (the `governor/` folder is enumerated, and the
`simulation/`, `dataplane/`, `demo/` adapters and their tests are all scanned), so adding
a file or reworking a document extends the check automatically rather than silently
escaping it.

One environment note, not a fitness-function issue: `node --test fitness/` (a bare
directory argument) hits a Node v24 test-runner quirk where the directory fails to
resolve. `package.json` therefore uses the shell-glob form, `node --test fitness/*.test.js`,
which is verified green on Node 22 and Node 24.
